Nested options: setDefault() → setOptions()

At a glance.

Type
BC break
setOptions() added
7.3
Old way deprecated
7.3
Old way removed
8.0

Since symfony/options-resolver 8.0, nested options can no longer be defined by passing a closure to setDefault(): use setOptions(), available since 7.3.

BC break

Since 4.2, a nested option was declared with setDefault(), with a closure whose first argument is type-hinted OptionsResolver.

// 4.2 – 7.4
$resolver->setDefault('spool', function (OptionsResolver $spoolResolver): void {});
// >= 8.0
$resolver->setOptions('spool', function (OptionsResolver $spoolResolver): void {});

Since 5.1, the fluent configuration does the same with default().

// 5.1 – 7.4
$resolver->define('spool')->default(function (OptionsResolver $spoolResolver): void {});
// >= 8.0
$resolver->define('spool')->options(function (OptionsResolver $spoolResolver): void {});

Deprecated 7.3 – 7.4

In 7.3 and 7.4, the code of BC break still works, but triggers a deprecation:

Since symfony/options-resolver 7.3: Defining nested options via "Symfony\Component\OptionsResolver\OptionsResolver::setDefault()" is deprecated and will be removed in Symfony 8.0, use "setOptions()" method instead.

Migration

symfony/options-resolver 8.0 throws no error if the code is not migrated.

setDefault() now only treats a closure as special when its first argument is type-hinted Options.

A closure type-hinted OptionsResolver becomes a plain default value.

// symfony/options-resolver 8.0, code not migrated
$resolver->setDefault('spool', function (OptionsResolver $spoolResolver): void {
    // never called
});

$resolver->resolve([]); // ['spool' => Closure]

The code then fails later, far from the cause, e.g. with Cannot use object of type Closure as array when reading $options['spool']['type'].

Fix every deprecation of 7.4 before upgrading: search for setDefault( calls whose closure takes an OptionsResolver argument.
