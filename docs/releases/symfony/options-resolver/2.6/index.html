BC breaks.6

Changes that can break existing code when upgrading from 2.5.

  • Turn Options into an interface implemented by OptionsResolver: Options::all() and Traversable are removed and option values can only be read within lazy options and normalizers
    Commit 642c119e0c Pull request #12156
  • Remove the array type hint from setRequired(), setAllowedValues(), addAllowedValues(), setAllowedTypes() and addAllowedTypes() of OptionsResolverInterface
    Commit 642c119e0c Pull request #12156
  • Make isRequired() return true for a required option that has a default value
    Commit 642c119e0c Pull request #12156
  • Make OptionDefinitionException extend LogicException instead of RuntimeException
    Commit 642c119e0c Pull request #12156
  • Normalizers are no longer executed for unset options and now run after the options are validated
    Commit 642c119e0c Pull request #12156
  • Throw UndefinedOptionsException instead of InvalidOptionsException when non-existing options are passed
    Commit 642c119e0c Pull request #12156

New features.2

New capabilities added by this version.

  • Merge Options into OptionsResolver with a new per-option API: setDefault(), hasDefault(), setNormalizer(), setDefined(), isDefined(), getDefinedOptions(), getRequiredOptions(), isMissing(), getMissingOptions(), remove() and clear()
    Commit 642c119e0c Pull request #12156
  • Allow setAllowedValues(), addAllowedValues(), setAllowedTypes() and addAllowedTypes() to take a single option name with its allowed values or types, and allow closures as allowed values
    Commit 642c119e0c Pull request #12156

Improvements.3

Enhancements of existing features.

  • Validate the allowed types of options before their allowed values in resolve()
    Commit a4f208b95b Pull request #11501
  • Throw a new NoSuchOptionException (extends OutOfBoundsException) when a lazy option or normalizer reads an undefined or unset option, with a clearer message
    Commit b93c4c072c Pull request #12294
  • Make the AccessException messages specific to the called method (e.g. "Default values cannot be set from a lazy option or normalizer.")
    Commit b93c4c072c Pull request #12294

Other changes.8

No impact on your code.

  • Update the dev-master branch alias to 2.6-dev in composer.json
    Commit a11645c637
  • Add a light-weight static API to resolve options: resolve(), validateNames(), validateRequired(), validateTypes() and validateValues() of Options, and a new OptionsConfig class (reverted before 2.6.0)
    Commit 90660255a2 Pull request #11716
  • Revert the light-weight static API (Options::resolve(), Options::validate*() and OptionsConfig) added earlier during 2.6 development
    Commit 453882cd03
  • Deprecate OptionsResolverInterface, replaceDefaults(), setOptional() (use setDefined()), isKnown() (use isDefined()) and the former Options methods set(), get(), has(), replace() and overload()
    Commit 642c119e0c Pull request #12156
  • Fix count() on Options within lazy options and normalizers to return the number of set options
    Commit 6c2130f578 Pull request #12294
  • Fix the formatting of invalid value exception messages: allowed types joined with "or" and accepted values correctly listed
    Commit dc1250c2b8 Pull request #12294
  • Fix calling resolve() from within a lazy option or normalizer: it now throws an AccessException
    Commit 8bcbcc3fd7 Pull request #12294
  • Document in the CHANGELOG the BC break of UndefinedOptionsException replacing InvalidOptionsException for non-existing options
    Commit 0b0bfc03d5 Pull request #12384
