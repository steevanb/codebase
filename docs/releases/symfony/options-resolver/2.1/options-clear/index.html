Options::clear()

At a glance

Type
New feature
clear() added
2.1

Since symfony/options-resolver 2.1, Options::clear() removes all the options, with their lazy values and their normalizers.

Remove all options

Options cleared

  • Declaration of Options::clear() in v2.1.0
PHP 5.3
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('firstName', 'foo');
$options->set('key', 'bar');
$options->clear();

// array()
$all = $options->all();
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('firstName', 'foo');
$options->set('key', 'bar');
$options->clear();

// []
$all = $options->all();

The normalizers

Normalizers cleared

  • Symfony 2.x documentation: Option Normalization
  • Declaration of Options::clear() in v2.1.0
PHP 5.3
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('email', 'foo@bar.com');
$options->setNormalizer(
    'email',
    function (Options $options, $value) {
        return strtoupper($value);
    }
);
$options->clear();
$options->set('email', 'foo@bar.com');

// "email" not normalized: clear() also removes the normalizers
// array('email' => 'foo@bar.com')
$all = $options->all();

Read-only once read

Once an option is read, the options cannot be cleared anymore.

Cleared after a read

  • Declaration of Options::clear() in v2.1.0
PHP 5.3
use Symfony\Component\OptionsResolver\Exception\OptionDefinitionException;
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('key', 'foo');
$options->get('key');

// OptionDefinitionException: Options cannot be cleared anymore once options have been read.
$options->clear();
