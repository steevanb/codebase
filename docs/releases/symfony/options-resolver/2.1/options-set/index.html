Options::set($option, $value)

At a glance

Type
New feature
set() added
2.1

Since symfony/options-resolver 2.1, Options::set() sets the value of an option, lazy when it is a closure typed with Options.

Set an option

Value

  • Declaration of Options::set() in v2.1.0
PHP 5.3
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('key', 'foo');

// array('key' => 'foo')
$all = $options->all();
use Symfony\Component\OptionsResolver\Options;

Lazy value

A closure whose first argument is type-hinted Options is only called when the option is read, and can read the other options.

  • Symfony 2.x documentation: Default Values that Depend on another Option
  • Declaration of Options::set() in v2.1.0
PHP 5.3
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('firstName', 'foo');
$options->set('key', function (Options $options) {
    return 'foo' === $options->get('firstName') ? 'bar' : 'baz';
});

// 'bar'
$key = $options->get('key');
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('firstName', 'foo');
$options->set('key', fn (Options $options): string => 'foo' === $options->get('firstName') ? 'bar' : 'baz');

// 'bar'
$key = $options->get('key');

Lazy value reading an option set after it

The closure is only called when the option is read, so it can read an option set after it.

  • Symfony 2.x documentation: Default Values that Depend on another Option
  • Declaration of Options::set() in v2.1.0
PHP 5.3
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('key', function (Options $options) {
    return $options->get('firstName');
});
$options->set('firstName', 'foo');

// 'foo'
$key = $options->get('key');
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('key', fn (Options $options): string => $options->get('firstName'));
$options->set('firstName', 'foo');

// 'foo'
$key = $options->get('key');

Closure not typed with Options

A closure whose first argument, $options, is not type-hinted Options is not lazy: it is the value of the option.

  • Declaration of Options::set() in v2.1.0
PHP 5.3
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('key', function ($options) {
    return 'foo';
});

// true
$isClosure = $options->get('key') instanceof Closure;
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('key', fn ($options): string => 'foo');

// true
$isClosure = $options->get('key') instanceof Closure;
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('key', fn (mixed $options): string => 'foo');

// true
$isClosure = $options->get('key') instanceof Closure;

Closure without argument

A closure without argument is not lazy either: it is the value of the option.

  • Declaration of Options::set() in v2.1.0
PHP 5.3
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('key', function () {
    return 'foo';
});

// true
$isClosure = $options->get('key') instanceof Closure;
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('key', fn (): string => 'foo');

// true
$isClosure = $options->get('key') instanceof Closure;

Order after a replacement

set() removes the option before adding it again, at the end of the options.

  • Declaration of Options::set() in v2.1.0
PHP 5.3
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('firstName', 'foo');
$options->set('lastName', 'bar');
$options->set('firstName', 'baz');

// array('lastName' => 'bar', 'firstName' => 'baz')
$all = $options->all();
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('firstName', 'foo');
$options->set('lastName', 'bar');
$options->set('firstName', 'baz');

// ['lastName' => 'bar', 'firstName' => 'baz']
$all = $options->all();

Previous value discarded

A second argument, $previousValue, receives null: set() removes the previous value first, unlike overload().

  • Symfony 2.x documentation: Default Values that Depend on another Option
  • Declaration of Options::set() in v2.1.0
PHP 5.3
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('key', 'foo');
$options->set('key', function (Options $options, $previousValue) {
    return $previousValue;
});

// null
$key = $options->get('key');
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('key', 'foo');
$options->set('key', fn (Options $options, $previousValue) => $previousValue);

// null
$key = $options->get('key');
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('key', 'foo');
$options->set('key', fn (Options $options, mixed $previousValue): mixed => $previousValue);

// null
$key = $options->get('key');

Read-only once read

Once an option is read, the options cannot be set, overloaded, replaced, removed or cleared anymore.

Reading one option locks all of them.

Set after has($option)

  • Declaration of Options::set() in v2.1.0
  • Declaration of Options::has() in v2.1.0
PHP 5.3
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('key', 'foo');
$options->has('key');
// has() does not read the option: the options can still be set
$options->set('key', 'bar');

// array('key' => 'bar')
$all = $options->all();
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('key', 'foo');
$options->has('key');
// has() does not read the option: the options can still be set
$options->set('key', 'bar');

// ['key' => 'bar']
$all = $options->all();
