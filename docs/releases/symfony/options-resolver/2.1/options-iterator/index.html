Options implements Iterator

At a glance

Type
New feature
Iterator added
2.1

Since symfony/options-resolver 2.1, Options implements Iterator: a foreach loops over the options, reading each of them with get().

PHP 5.3
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('firstName', 'foo');
$options->set(
    'key',
    function (Options $options) {
        return strtoupper($options->get('firstName'));
    }
);

// Calls $options->get('key'): the lazy option is evaluated
// array('firstName' => 'foo', 'key' => 'FOO')
$all = iterator_to_array($options);

PHP 5.3
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('firstName', 'foo');
$options->set('lastName', 'bar');

$pairs = array();
// 2 iterations instead of 4: the options have a single pointer, moved to the end by the inner loop
// array('firstName firstName', 'firstName lastName')
foreach ($options as $outer => $outerValue) {
    foreach ($options as $inner => $innerValue) {
        $pairs[] = $outer . ' ' . $inner;
    }
}

Set inside a loop

  • Declaration of Options::current() in v2.1.0

PHP 5.3
use Symfony\Component\OptionsResolver\Exception\OptionDefinitionException;
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('key', 'foo');

foreach ($options as $key => $value) {
    // OptionDefinitionException: Options cannot be set anymore once options have been read.
    $options->set('firstName', 'bar');
}

Read-only once read

A loop reads each option: the options cannot be set anymore.
