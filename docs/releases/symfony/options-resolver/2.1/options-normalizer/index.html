Options::setNormalizer($option, \Closure $normalizer)

At a glance

Type
New feature
Method added
2.1

Since symfony/options-resolver 2.1, Options::setNormalizer() transforms the value of an option when it is read.

Normalize an option

Option normalized

  • Symfony 2.x documentation: Option Normalization
  • Declaration of Options::setNormalizer() in v2.1.0
PHP 5.3
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('email', 'foo@bar.com');
$options->setNormalizer(
    'email',
    function (Options $options, $value) {
        return strtoupper($value);
    }
);

// 'FOO@BAR.COM'
$email = $options->get('email');
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('email', 'foo@bar.com');
$options->setNormalizer(
    'email',
    fn (Options $options, string $value): string => strtoupper($value)
);

// 'FOO@BAR.COM'
$email = $options->get('email');

Own option read

  • Symfony 2.x documentation: Option Normalization
  • Declaration of Options::setNormalizer() in v2.1.0
  • Declaration of Options::get() in v2.1.0
PHP 5.3
use Symfony\Component\OptionsResolver\Exception\OptionDefinitionException;
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('email', 'foo@bar.com');
$options->setNormalizer(
    'email',
    // The value of the option is given in $value: reading the option calls the normalizer again
    function (Options $options, $value) {
        return strtoupper($options->get('email'));
    }
);

// OptionDefinitionException: The options "email" have a cyclic dependency.
$options->get('email');

Read-only once read

Once an option is read, normalizers cannot be added anymore.
