Options::has($option)

At a glance

Type
New feature
has() added
2.1

Since symfony/options-resolver 2.1, Options::has() tells whether an option is set, without reading it nor evaluating it when it is lazy.

Check an option

Option set

  • Declaration of Options::has() in v2.1.0
PHP 5.3
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('key', 'foo');

// true
$hasKey = $options->has('key');

Null value with isset()

Unlike with an array, isset() gives true for an option set to null: it calls has(), which does not read the value.

// Calls $options->has('key')
// true
$hasKey = isset($options['key']);

Optional options

In a lazy option, has() tells whether an optional option was given to resolve().

Optional option given

The order of the calls to setOptional() and setDefaults() does not matter: the lazy option is only evaluated by resolve().

  • Symfony 2.x documentation: Options without Default Values
  • Symfony 2.x documentation: Default Values that Depend on another Option
  • Declaration of Options::has() in v2.1.0
PHP 5.3
use Symfony\Component\OptionsResolver\Options;
use Symfony\Component\OptionsResolver\OptionsResolver;

$resolver = new OptionsResolver();
$resolver
    ->setOptional(array('firstName'))
    ->setDefaults(array(
        'hasFirstName' => function (Options $options) {
            return $options->has('firstName');
        },
    ));

// array('hasFirstName' => true, 'firstName' => 'foo')
$options = $resolver->resolve(array('firstName' => 'foo'));
use Symfony\Component\OptionsResolver\Options;
use Symfony\Component\OptionsResolver\OptionsResolver;

$resolver = (new OptionsResolver())
    ->setOptional(['firstName'])
    ->setDefaults([
        'hasFirstName' => function (Options $options) {
            return $options->has('firstName');
        },
    ]);

// ['hasFirstName' => true, 'firstName' => 'foo']
$options = $resolver->resolve(['firstName' => 'foo']);
use Symfony\Component\OptionsResolver\Options;
use Symfony\Component\OptionsResolver\OptionsResolver;

$resolver = (new OptionsResolver())
    ->setOptional(['firstName'])
    ->setDefaults([
        'hasFirstName' => fn (Options $options): bool => $options->has('firstName'),
    ]);

// ['hasFirstName' => true, 'firstName' => 'foo']
$options = $resolver->resolve(['firstName' => 'foo']);
use Symfony\Component\OptionsResolver\Options;
use Symfony\Component\OptionsResolver\OptionsResolver;

$resolver = new OptionsResolver()
    ->setOptional(['firstName'])
    ->setDefaults([
        'hasFirstName' => fn (Options $options): bool => $options->has('firstName'),
    ]);

// ['hasFirstName' => true, 'firstName' => 'foo']
$options = $resolver->resolve(['firstName' => 'foo']);

Option with a default value

An option with a default value always exists, even null: has() cannot tell whether it was given to resolve().

use Symfony\Component\OptionsResolver\OptionsResolver;

Not a read

Unlike get(), has() does not lock the options.

Set after has($option)

The options can still be set after a call to has().

  • Declaration of Options::has() in v2.1.0
PHP 5.3
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('key', 'foo');
$options->has('key');
$options->set('key', 'bar');

// array('key' => 'bar')
$all = $options->all();
use Symfony\Component\OptionsResolver\Options;

$options = new Options();
$options->set('key', 'foo');
$options->has('key');
$options->set('key', 'bar');

// ['key' => 'bar']
$all = $options->all();
