Nested options: setDefault() → setOptions() BC break

Since symfony/options-resolver 8.0, nested options can no longer be defined by passing a closure to setDefault(): use setOptions(), available since 7.3.

7.3
setOptions() added, old way deprecated
8.0
Old way removed

Before <= 7.2

A nested option was declared with setDefault() (or default() with the fluent configuration), with a closure whose first argument is type-hinted OptionsResolver. 

$resolver->setDefault('spool', function (OptionsResolver $spoolResolver): void {
    // ...
});

$resolver->define('spool')->default(function (OptionsResolver $spoolResolver): void {
    // ...
});

In 7.3 and 7.4, this code still works but triggers a deprecation: 

Since symfony/options-resolver 7.3: Defining nested options via
"Symfony\Component\OptionsResolver\OptionsResolver::setDefault()" is deprecated
and will be removed in Symfony 8.0, use "setOptions()" method instead.

Now >= 7.3

Only the method changes: setOptions(), or options() with the fluent configuration. The closure stays the same, including its optional second argument Options $parent. 

$resolver->setOptions('spool', function (OptionsResolver $spoolResolver): void {
    // ...
});

$resolver->define('spool')->options(function (OptionsResolver $spoolResolver): void {
    // ...
});

If you don't migrate

symfony/options-resolver 8.0 throws no error. setDefault() now only treats a closure as special when its first argument is type-hinted Options. A closure type-hinted OptionsResolver becomes a plain default value. 

// symfony/options-resolver 8.0, code not migrated
$resolver->setDefault('spool', function (OptionsResolver $spoolResolver): void {
    // never called
});

$resolver->resolve([]); // ['spool' => Closure]

The code then fails later, far from the cause, e.g. with Cannot use object of type Closure as array when reading $options['spool']['type']. Fix every deprecation of 7.4 before upgrading: search for setDefault( calls whose closure takes an OptionsResolver argument.
